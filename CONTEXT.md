# moldig

moldig scans, audits and cleans the configuration that AI coding harnesses leave behind — skills, MCP servers, context files and memories — across every project on a machine, from one terminal UI.

## Language

### The tool

**Harness**:
An AI coding tool whose on-disk configuration moldig reads (Claude Code, Codex, Cursor, Gemini CLI, Copilot, OpenCode).
_Avoid_: AI, IA, agent, tool, IDE, assistant

**Adapter**:
The module that knows where one harness keeps its files and turns them into index entities. Read-only.
_Avoid_: plugin, connector, scanner, provider

**Index**:
The unified, harness-agnostic model of everything moldig found: entities plus the edges between them. The contract shared by the CLI and the app.
_Avoid_: database, catalog, inventory

**Scan**:
The read-only pass that runs every adapter and builds the index. It never executes a harness, an agent or an MCP server.
_Avoid_: analyze, crawl, audit (audit is what the detectors do on top of a scan)

**Finding**:
One thing moldig thinks you should look at, filed under exactly one category and pointing at one or more entities.
_Avoid_: issue, warning, problem, result

**Category**:
A CleanMyMac-style bucket of findings: duplicate, orphan, bloat, drift, shadow memory, autogenerated, harness cache.
_Avoid_: rule, check, group

**Action**:
An operation moldig performs on selected items after a confirmation: clean, delete, update or open. Selections are grouped by action and each group is confirmed as a whole before anything runs.
_Avoid_: operation, command (commands are the CLI's verbs), fix

**Clean**:
The sweep: removing selected harness-owned items (memory files, harness cache), with a preview and always recoverable. Human-owned items are never part of a clean.
_Avoid_: purge, sweep, delete (delete is the targeted action)

**Delete**:
Removing one explicitly selected item, human-owned included, after confirmation; always recoverable (trash, or a backup when a config entry is removed).
_Avoid_: remove, clean, uninstall

**Update**:
Bringing an installed skill to its origin's current state, with a preview of what changes.
_Avoid_: upgrade, sync, refresh

**Headline number**:
The single estimate at the top of a report: tokens wasted per session.
_Avoid_: score, hook, metric

### What moldig finds

**Skill**:
A reusable instruction package a harness loads on demand: a folder with a `SKILL.md`. Copies may live in many projects at different versions.
_Avoid_: command, prompt, plugin

**MCP server**:
An MCP server configured for a harness at some scope.
_Avoid_: MCP (alone), tool, integration

**Context file**:
An instruction file a human writes and a harness loads at session start (CLAUDE.md, AGENTS.md, GEMINI.md, Cursor rules).
_Avoid_: rules, instructions, prompt file, system prompt

**Memory file**:
A file a harness writes for itself across sessions (Claude Code's auto-memory `MEMORY.md` and its per-fact files).
_Avoid_: context, notes, state

**Shadow memory**:
Memory files kept outside the project they describe: not git-tracked, not visible from the repo.
_Avoid_: hidden memory, global memory

**Agent definition**:
A custom sub-agent configuration file a harness can spawn (e.g. `.claude/agents/*.md`).
_Avoid_: agent (ambiguous with harness), persona

**Harness cache**:
State a harness keeps for its own operation and documents as safe to sweep: session transcripts, tool results, shell snapshots, rotating backups, plugin and marketplace clones.
_Avoid_: junk, temp files, logs, state

**Project**:
A directory on disk that a harness has worked in and that carries its own configuration. Not necessarily a git repository.
_Avoid_: repo, workspace, codebase

**Scope**:
Where a configuration item applies: user (global, under `~`), project (inside the project, shared) or local (inside the project, personal).
_Avoid_: level, layer

### Ownership and sharing

**Human-owned**:
An item a person put in place on purpose — wrote it, installed it or configured it: context files, skills (third-party ones included), agent definitions, MCP servers.
_Avoid_: user files, manual, authored (a third-party skill is human-owned but not authored by the user)

**Harness-owned**:
An item a harness produced for its own use: memory files and harness cache.
_Avoid_: automatic, generated (autogenerated is reserved for context files), system files

**Shared**:
A project-scoped item tracked by the project's git repository, and therefore possibly relied on by collaborators. Every suggested action on a shared item carries a warning.
_Avoid_: committed, team, collaborative

### Relationships and judgements

**Origin**:
Where a skill was installed from: a git ref, a marketplace entry or an npm package.
_Avoid_: source, upstream (upstream is the origin's current state)

**Drift**:
The distance between an installed copy of a skill and its origin's current state.
_Avoid_: outdated, stale (stale is for memory)

**Duplicate**:
The same skill installed in more than one place, possibly at different versions.
_Avoid_: copy, clone

**Orphan**:
A configured item that nothing references, or whose target no longer exists on disk (a project breadcrumb whose directory is gone counts).
_Avoid_: dead, broken, unused, ghost

**Bloat**:
Context or memory that costs tokens every session without adding actionable guidance.
_Avoid_: noise, junk, large file

**Autogenerated**:
A context file carrying the fingerprints of a harness's `/init` template rather than a human's failure patterns.
_Avoid_: template, boilerplate, generated
