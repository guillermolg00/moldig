# moldig

moldig scans, audits and cleans the configuration that AI coding harnesses leave behind — skills, MCP servers, context files and memories — across every project on a machine, from one terminal UI.

## Language

### The tool

**Harness**:
An AI coding tool whose on-disk configuration moldig reads (Claude Code, Codex, Cursor, Gemini CLI, Copilot, OpenCode).
_Avoid_: AI, IA, agent, tool, IDE, assistant

**Adapter**:
The module that knows where one harness keeps its files and turns them into index entities: one per harness, plus one for the stores several harnesses share. Read-only.
_Avoid_: plugin, connector, scanner, provider

**Index**:
The unified, harness-agnostic model of everything moldig found: harnesses, projects, breadcrumbs, entities and the edges between them. The contract shared by the CLI and the app.
_Avoid_: database, catalog, inventory

**Entity**:
One thing the index knows about — a context file, skill, MCP server entry, memory file, agent definition, harness cache unit, plugin or settings file — with its scope, ownership and metrics. One entity per real thing, whichever harnesses reach it.
_Avoid_: item (the UI word), node, record, object

**Edge**:
A typed connection between two entities, between an entity and a harness, or from an entity to a name nothing resolves, carrying its evidence and confidence: names, names a tool, references, loaded by, duplicates, originates from, shadows, imports, provided by, lists.
_Avoid_: link (reserved for symlinks), dependency, relation, reference

**Reader**:
A harness that loads a given context file, skill, memory file, MCP server, agent definition or plugin, with its own verdict on whether, how much and under which name it enters a session.
_Avoid_: consumer, subscriber

**Scan**:
The read-only pass that runs every adapter and builds the index. It never executes a harness, a sub-agent or an MCP server.
_Avoid_: analyze, crawl, audit (audit is what the detectors do on top of a scan)

**Root**:
A directory the user points moldig at. The scan is limited to the projects under it, breadcrumbs included, and it is walked for project markers. Without a root, moldig scans every project the breadcrumbs name. Reserved for this meaning: the top directory of a git repository is called the repository directory, never the root.
_Avoid_: path, folder, workspace, scope, target

**Finding**:
One thing moldig thinks you should look at, filed under exactly one category, carrying a severity, and pointing at one or more targets: entities, breadcrumbs or a locator inside a settings file.
_Avoid_: issue, warning, problem, result

**Warning**:
Something a scan or audit could not do or did only partly: a file it could not parse, a target it could not stat in time, a tokenizer that fell back. Not a finding.
_Avoid_: error, issue, finding

**Category**:
A CleanMyMac-style bucket of findings: duplicate, orphan, bloat, drift, shadow memory, autogenerated, harness cache, exposure.
_Avoid_: rule, check, group

**Action**:
An operation moldig performs on selected items after a confirmation: clean, delete, update or open. Selections are grouped by action and each group is confirmed as a whole before anything runs.
_Avoid_: operation, command (commands are the CLI's verbs), fix

**Clean**:
The sweep: removing selected harness-owned items (memory files, harness cache), with a preview and always recoverable. Human-owned items, and harness state the harness itself documents as kept, are never part of a clean; on a volume without a trash nothing is removed.
_Avoid_: purge, sweep, delete (delete is the targeted action)

**Disposition**:
Where a removed item goes, decided before anything moves: the trash, a backup followed by an edit, or the harness's own command; or the reason it stays.
_Avoid_: destination, strategy, mode

**Delete**:
Removing one explicitly selected item, human-owned included, after confirmation; always recoverable: the trash for files, directories and links, a backup before a config or lock entry is edited, or the harness's own command when moldig never edits that file. Removing a skill for one harness trashes that link; removing the skill takes every link and its lock entry with it. An orphan Project is also one explicit Delete target: its complete harness records are removed after a second confirmation, then the Index is rebuilt.
_Avoid_: remove, clean, uninstall

**Purge**:
The interactive CLI command for selecting orphan Projects and applying one aggregate Delete to each. Every Project starts selected, the user may exclude Projects, and the Delete still asks twice. Purge is a command name, never an Action and never a synonym for Clean.
_Avoid_: purge action, purge sweep, clean missing projects

**Update**:
Bringing an installed skill or plugin to its origin's current state by delegating to its installer, with a preview of what changes; a locally modified copy is backed up first.
_Avoid_: upgrade, sync, refresh

**Headline number**:
The estimate at the top of a report: tokens per session for the focused project and each harness, split into what every session pays (user scope) and what that project adds. Counts only what the user controls — context files (rules included), imports, the loaded slice of memory files, skill descriptions — never the harness's own system prompt or tool schemas.
_Avoid_: score, hook, metric, total (the inventory sum)

### What moldig finds

**Skill**:
A reusable instruction package a harness loads on demand: a directory with a `SKILL.md`, or a single file a harness lists as a command. One skill per real directory; a symlink a harness reads it through is a placement, not another skill; a link that points at nothing is still one skill, marked dangling. Copies may live in many projects at different versions.
_Avoid_: command, prompt, plugin, link, alias

**Placement**:
One path a harness reaches a skill through — the real directory itself or a link to it — with the scope and project of that path.
_Avoid_: location, install, copy (a copy is another skill)

**MCP server**:
An MCP server configured for a harness at some scope.
_Avoid_: MCP (alone), tool, integration

**Context file**:
An instruction file a human writes and a harness loads at session start or when its rule matches (CLAUDE.md, AGENTS.md, GEMINI.md, Cursor rules).
_Avoid_: rules, instructions, prompt file, system prompt

**Memory file**:
A file a harness writes for itself across sessions (Claude Code's auto-memory `MEMORY.md` and its per-fact files, Codex's memories). One file at a time: an index file, a fact file or another file in the unit; the directory they share is the memory unit.
_Avoid_: context, notes, state, memory (alone)

**Shadow memory**:
Memory files kept outside the project they describe: not git-tracked, not visible from the repo.
_Avoid_: hidden memory, global memory

**Agent definition**:
A custom sub-agent configuration file a harness can spawn (e.g. `.claude/agents/*.md`).
_Avoid_: agent (ambiguous with harness), persona

**Plugin**:
An installed bundle that provides skills, agent definitions, MCP servers or hooks to a harness as one unit (Claude Code plugins, Gemini extensions). What it provides is removed only through the plugin.
_Avoid_: extension (Gemini's word), marketplace (where it comes from), package

**Settings file**:
A configuration or state file a harness reads — settings, MCP config, lock file, plugin registry, hooks file, policy file, manifest, credentials — that may hold entries moldig models on their own.
_Avoid_: config (alone), preferences, dotfile

**Entry**:
A keyed value inside a settings file that moldig models as an entity of its own — today an MCP server; lock entries and breadcrumb records are addressed by their locator, not modelled. Deleting an entry edits the file with a backup, or is delegated to the harness's own command when moldig never edits that file.
_Avoid_: line, record, field, key

**Harness cache**:
State a harness keeps for its own operation — session transcripts, tool results, shell snapshots, rotating backups, plugin and marketplace clones, databases — listed by the unit the harness itself sweeps (a session, a plugin version, a clone, or a single file when that is what the harness sweeps), never split below that unit nor grouped above it. Only what the harness documents as sweepable may be preselected; the rest is shown and left alone.
_Avoid_: junk, temp files, logs, state, leftovers

**Project**:
A directory on disk that a harness has worked in and that is a git repository (or a worktree of one) or carries its own harness configuration. One project per real directory, whichever harnesses name it. Configuration nested inside a repository, outside any nested repository, belongs to the repository's project; a nested repository is a project of its own; a linked worktree belongs to its main repository's project. A bare directory such as the home directory is never a project, even when a harness has worked there. A project whose directory is gone remains a Project, marked orphan, so what every harness left about it stays together and can be selected as one aggregate Delete target.
_Avoid_: repo, workspace, codebase, folder

**Breadcrumb**:
A harness's own record that it worked in a directory: an absolute path kept in the harness's user-scope state (a projects entry, a trust entry, a workspace record, a session's working directory, a slug directory). Each breadcrumb carries its kind.
_Avoid_: trace, entry (an Entry is a value inside a settings file; a breadcrumb is evidence), history, record, reference

**Stray**:
Harness-owned state whose breadcrumb names no project: a bare directory such as the home directory, or a slug that cannot be resolved. Listed under the harness's user scope and cleanable like any harness-owned item.
_Avoid_: orphan (reserved for the Orphan category), homeless, junk, misc

**Scope**:
Where a configuration item applies: system (set by an organisation or the OS, outside `~`), user (global, under `~`), project (inside the project, meant for the repository) or local (inside the project, meant for one person).
_Avoid_: level, layer, enterprise, managed, global (global is the user scope)

### Ownership and sharing

**Human-owned**:
An item a person put in place on purpose — wrote it, installed it or configured it: context files, skills (third-party ones included), agent definitions, MCP servers, plugins.
_Avoid_: user files, manual, authored (a third-party skill is human-owned but not authored by the user)

**Harness-owned**:
An item a harness produced for its own use, or ships with itself: memory files, harness cache, and the skills a harness bundles (never actionable).
_Avoid_: automatic, generated (autogenerated is reserved for context files), system files

**Shared**:
A project- or local-scoped item tracked by the project's git repository, and therefore possibly relied on by collaborators. Every suggested action on a shared item is flagged.
_Avoid_: committed, team, collaborative

### Relationships and judgements

**Origin**:
Where a skill or plugin was installed from — a git ref, a marketplace entry, an npm package, a well-known URL or a local path — as recorded in the lock file.
_Avoid_: source, upstream (upstream is the origin's current state), provenance, installer (the tool that recorded it)

**Installer**:
The tool that recorded an item's origin and owns its lock or registry: Vercel's skills CLI, Claude Code's plugin command, Gemini's extensions command, or a plain git clone. Update delegates to it; an item without one cannot be updated.
_Avoid_: package manager, source (source is where the origin points)

**Drift**:
The distance between an installed copy of a skill and its origin's current state. Offline, moldig can only tell unknown, none, locally modified or copies differ; the distance to upstream needs the network.
_Avoid_: outdated, stale (stale is for memory)

**Duplicate**:
The same skill or MCP server present in more than one place as distinct copies, possibly at different versions. Two placements of one directory are not duplicates.
_Avoid_: copy, clone, symlink, mirror

**Orphan**:
A configured item that nothing references, or whose target no longer exists on disk (a project breadcrumb whose directory is gone counts).
_Avoid_: dead, broken, unused, ghost

**Unreachable**:
A breadcrumb target that sits on a volume that is not mounted right now, or that could not be checked in time. Not an orphan: nothing is suggested for it until the volume is back.
_Avoid_: missing, offline, gone, disconnected

**Bloat**:
Context or memory that costs tokens every session without adding actionable guidance.
_Avoid_: noise, junk, large file

**Live**:
An item a harness is using right now: a running session's state, a plugin version in use, a worktree still registered. Shown, never selectable.
_Avoid_: active, open, busy, locked

**Exposure**:
A secret sitting where it should not: in a git-tracked configuration, or in a configuration nothing reads.
_Avoid_: leak, vulnerability, security issue

**Autogenerated**:
A context file carrying the fingerprints of a harness's `/init` template rather than a human's failure patterns.
_Avoid_: template, boilerplate, generated
